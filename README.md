# 🏠 Roommate — 룸메이트 생필품 소진 예측 및 비용 정산 시스템

> 공동생활에서 생필품이 **언제 떨어질지** 미리 알려주고, 나눠 낸 돈을 **최소 송금 횟수로** 정산해 주는 Java 프로그램

선문대학교 SW중심대학 기업연계 프로젝트 · JAVA 응용 프로젝트(PBL)

---

## 📌 프로젝트 소개

룸메이트, 자취, 기숙사처럼 여러 명이 함께 사는 환경에서는 화장지·세제 같은 공동 생필품을 함께 사고 함께 씁니다.
그런데 대부분 메모장이나 메신저로 관리하다 보니 이런 문제가 생깁니다.

- 구매 이력이 체계적으로 남지 않아 **다 떨어진 뒤에야** 알게 됨
- N명이 서로 다른 금액을 냈을 때 수작업으로 정산하면 **최대 N×(N-1)/2번**의 1:1 송금이 생길 수 있고, 계산 실수도 잦음

**Roommate**는 구매 이력을 바탕으로 품목별 소진 시점을 예측하고, 그리디 알고리즘으로 정산을 자동화해서 이 문제를 해결합니다.

### 기존 방식과 비교

| 구분 | 기존 방식 (수기 관리) | Roommate |
|---|---|---|
| 소진 시점 파악 | 소진 후에야 인지 | 구매 이력 기반 사전 예측 알림 |
| 정산 방식 | 1:1 수동 계산, 최대 N×(N-1)/2번 송금 | 그리디 알고리즘 기반 최소 송금 자동 계산 |
| 기록 관리 | 메모장·메신저 등 비정형 기록 | 구조화된 데이터 기반 이력 관리 |
| 오류 가능성 | 수작업 계산 오류 | 알고리즘 자동 계산으로 오류 최소화 |

## 🧠 핵심 알고리즘

### 1. 소진 시점 예측 — 가중 이동평균 (Weighted Moving Average)

같은 품목의 구매 간격을 기록해 두고, **최근 간격일수록 높은 가중치**를 줘서 평균 소진 주기를 계산합니다.

```
예상 소진일 = 마지막 구매일 + Σ(wᵢ × 구매간격ᵢ) / Σwᵢ      (최근일수록 wᵢ ↑)
```

- 1단계: 단순 평균으로 구현
- 2단계: 가중 이동평균으로 고도화 → 생활 패턴 변화에 더 빠르게 반응

### 2. 비용 정산 — 그리디 기반 최소 송금

1. 참여자별 **순 잔액** 계산 (`낸 돈 − 부담해야 할 돈`)
2. 받을 사람(+)과 보낼 사람(−)을 각각 `PriorityQueue`(최대 힙)에 넣음
3. 가장 많이 받을 사람과 가장 많이 보낼 사람을 꺼내 `min(받을 금액, 보낼 금액)`만큼 송금 처리
4. 남은 잔액이 있으면 다시 큐에 넣고, 큐가 빌 때까지 반복

```
예) A가 60,000원, B가 0원, C가 30,000원, D가 10,000원 지출 (1인당 부담 25,000원)
    잔액: A +35,000 / C +5,000 / B −25,000 / D −15,000
    →  B → A : 25,000원
       D → A : 10,000원
       D → C :  5,000원      (총 3번 송금으로 정산 완료)
```

### 🔮 향후 개발 계획

#### 1. 데이터 저장소: txt 파일 → 데이터베이스(MySQL + JDBC)
현재는 품목·구매 이력을 txt 파일에 저장하지만, 데이터가 늘어나면 검색·수정이 느려지고 여러 사용자가 동시에 쓰기 어렵습니다. 이를 **MySQL**로 옮기고 **JDBC**로 연동할 예정입니다.

- 데이터 접근 코드를 **DAO 패턴**으로 분리 → 파일 저장 방식에서 DB 방식으로 교체할 때 다른 로직은 그대로 유지
- 예상 테이블 구성 (초안)

  | 테이블 | 주요 컬럼 |
  |---|---|
  | `member` | id, name |
  | `item` | id, name, category |
  | `purchase` | id, item_id, member_id, price, quantity, purchase_date |

- 기존 txt 데이터를 DB로 옮기는 마이그레이션 기능 제공
- `PreparedStatement` 사용으로 SQL 인젝션 방지

#### 2. 사용자 인터페이스: 콘솔 입력 → GUI(Swing)
콘솔에서 번호를 입력하는 방식을 **Swing 기반 GUI**로 바꿔 누구나 쉽게 쓸 수 있도록 할 예정입니다.

- 품목 목록과 구매 이력을 `JTable`로 표시
- 버튼·입력 폼으로 품목 등록 / 구매 기록 추가
- 소진 임박 품목 강조 표시 및 알림 팝업
- 정산 결과(누가 누구에게 얼마)를 한눈에 보여주는 화면
- 이벤트 리스너 기반으로 화면(View)과 로직(Service)을 분리해 콘솔 버전의 핵심 로직을 그대로 재사용

```
[현재]  Console 입력  →  Service(로직)  →  txt 파일
[목표]  Swing GUI    →  Service(로직)  →  DAO  →  MySQL (JDBC)
```
