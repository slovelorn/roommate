# 🏠 Roommate — 룸메이트 생필품 소진 예측 및 비용 정산 시스템

> 공동생활에서 생필품이 **언제 떨어질지** 미리 알려주고, 나눠 낸 돈을 **적은 송금 횟수로** 정산해 주는 Java 프로그램

선문대학교 SW중심대학 기업연계 프로젝트 · JAVA 응용 프로젝트(PBL)

---

## 📌 프로젝트 소개

룸메이트, 자취, 기숙사처럼 여러 명이 함께 사는 환경에서는 화장지·세제 같은 공동 생필품을 함께 사고 함께 씁니다.
그런데 대부분 메모장이나 메신저로 관리하다 보니 이런 문제가 생깁니다.

- 구매 이력이 체계적으로 남지 않아 **다 떨어진 뒤에야** 알게 됨
- N명이 서로 다른 금액을 냈을 때 수작업으로 정산하면 **최대 N×(N-1)/2번**의 1:1 송금이 생길 수 있고, 계산 실수도 잦음
- 영수증이나 대화 내용을 매번 손으로 옮겨 적어야 해서 기록이 빠지기 쉬움

**Roommate**는 구매 이력을 바탕으로 품목별 소진 시점을 예측하고, 그리디 알고리즘으로 정산을 자동화하며, LLM으로 자연어 문장을 구매 기록으로 바꿔 이 문제를 해결합니다.

### 기존 방식과 비교

| 구분 | 기존 방식 (수기 관리) | Roommate |
|---|---|---|
| 소진 시점 파악 | 소진 후에야 인지 | 구매 이력 기반 사전 예측 및 임박 경고 |
| 정산 방식 | 1:1 수동 계산, 최대 N×(N-1)/2번 송금 | 그리디 알고리즘으로 송금 횟수를 N-1번 이하로 자동 계산 |
| 정산 이력 | 어디까지 정산했는지 헷갈림 | 정산 완료 처리 후 이후 기록만 다음 정산에 반영 |
| 기록 입력 | 메모장·메신저 등 비정형 기록 | 문장 한 줄 입력 → AI가 품목·금액·구매자·날짜 자동 입력 |
| 기록 관리 | 흩어진 기록 | MySQL DB 기반 구조화된 이력 관리 |

## 🧠 핵심 알고리즘

### 1. 소진 시점 예측 — 단순 평균 / 가중 이동평균

같은 품목의 구매 날짜를 정렬해 **구매 간격**을 구한 뒤, 다음 구매일을 예측합니다. (구매 기록 2건 이상 필요)

```
단순 평균      : 예상 소진일 = 마지막 구매일 + Σ(구매간격ᵢ) / n
가중 이동평균  : 예상 소진일 = 마지막 구매일 + Σ(wᵢ × 구매간격ᵢ) / Σwᵢ   (wᵢ = 1, 2, 3, … 최근일수록 ↑)
```

```
예) 구매일 9/1 → 9/21 → 10/6 → 10/16   (간격 20일, 15일, 10일 : 소비가 늘어나는 중)
    단순 평균     : (20 + 15 + 10) / 3            = 15일 → 10/31
    가중 이동평균 : (20×1 + 15×2 + 10×3) / 6 ≈ 13일 → 10/29   ← 최근 변화를 더 빠르게 반영
```

- 한눈에 보기와 경고는 **가중 이동평균** 기준으로 판단합니다.
- D-day = 예상 소진일 − 오늘 → `D+` 지남 / `D-0 ~ D-3` 소진 임박(빨간색) / 그 외 여유

### 2. 비용 정산 — 그리디 기반 송금 매칭

1. **정산 대상 선택** : 아직 정산 완료 처리되지 않은 구매 기록만 사용
2. **순잔액 계산** : `낸 금액 − 1/N 부담액` (양수 = 받을 사람, 음수 = 보낼 사람)
3. 받을 사람(+)과 보낼 사람(−)을 각각 `PriorityQueue`(최대 힙)에 넣음
4. 가장 많이 받을 사람과 가장 많이 보낼 사람을 꺼내 `min(받을 금액, 보낼 금액)`만큼 송금 처리
5. 남은 잔액이 있으면 다시 큐에 넣고, 큐가 빌 때까지 반복

```
예) A가 60,000원, B가 0원, C가 30,000원, D가 10,000원 지출 (1인당 부담 25,000원)
    잔액: A +35,000 / C +5,000 / B −25,000 / D −15,000
    →  B → A : 25,000원
       D → A : 10,000원
       D → C :  5,000원      (총 3번 송금으로 정산 완료)
```

- 매 단계마다 최소 한 명의 잔액이 0이 되므로 송금은 **최대 N−1번**, 시간 복잡도는 O(N log N)입니다.
- 송금 횟수의 수학적 최솟값을 구하는 문제는 NP-hard이므로, 실용적인 그리디 근사를 사용합니다. 룸메이트 규모(2~6명)에서는 사실상 최적과 같은 결과를 냅니다.
- 총액이 인원수로 나누어떨어지지 않으면 나머지(최대 N−1원)는 정산에서 제외됩니다.

### 3. 정산 완료 처리

송금을 마친 뒤 **[정산 완료 처리]** 를 누르면, 현재 미정산 기록 전체에 오늘 날짜가 `settled_date`로 기록됩니다.
이후 정산은 그 뒤에 추가된 기록만으로 계산됩니다.

- 날짜 기준이 아니라 **기록마다 정산 여부를 표시**하므로, 정산 후에 지난 날짜로 늦게 입력한 기록도 다음 정산에 정확히 포함됩니다.
- 소진 예측은 정산 여부와 관계없이 전체 구매 이력을 사용합니다.

### 4. AI 자연어 입력 — LLM 응답 검증 파이프라인

```
사용자 문장 ─→ 프롬프트 구성 ─→ LLM 호출 ─→ JSON 추출 ─→ 값 검증 ─→ 입력 폼 채우기 ─→ 사용자 확인 후 저장
```

1. **프롬프트 제약** : 등록된 품목·룸메이트 목록, 오늘 날짜와 요일, 출력 형식(JSON 한 줄)을 함께 전달 → "어제", "지난주 금요일"도 날짜로 변환
2. **JSON 추출** : 응답에 설명이나 코드 블록이 붙어도 `{ … }` 부분만 추출
3. **검증** : 목록에 없는 품목·구매자, 0 이하 금액, 잘못되거나 미래인 날짜는 버림
4. **사람이 확정** : 알아낸 값만 폼에 채우고, 저장은 사용자가 [구매 기록 추가]를 눌러야 실행

> **LLM이 제안하고, 프로그램이 검증하고, 사람이 확정한다** — LLM 오답이 그대로 DB에 들어가지 않도록 설계했습니다.

- API 호출은 `SwingWorker`로 별도 스레드에서 실행해 응답을 기다리는 동안 화면이 멈추지 않습니다.
- API 키 누락·키 오류(HTTP 401/403)·서버 연결 실패를 구분해 안내합니다.

## 🏗 프로젝트 구조

```
ROOMMATE
├─ src
│  ├─ app    : Main, MainFrame, 각 탭 Panel, AppData, Refreshable     (실행 + 화면)
│  ├─ model  : Item, Purchase                                          (데이터 정의)
│  ├─ db     : DataStorage                                             (MySQL 저장/불러오기, JDBC)
│  ├─ logic  : ConsumptionPredictor, SettlementEngine                  (예측·정산 알고리즘)
│  └─ llm    : LlmClient, PurchaseParser, ParsedPurchase, NlInputPanel (AI 자연어 입력)
├─ lib       : mysql-connector-j, gson                                 (외부 라이브러리)
└─ sql       : schema.sql, add_settled_date.sql                        (DB 생성/변경 스크립트)
```

### 패키지 의존 관계

```
app ──→ db ──────→ model
app ──→ logic ───→ model
app ──→ llm
```

- 의존 방향이 한쪽으로만 흐르도록 설계했습니다. `model`, `db`, `logic`, `llm`은 화면(`app`)을 알지 못합니다.
- 실제로 **콘솔 → Swing GUI** 전환 시 `logic` 패키지는 한 줄도 수정하지 않았고, **txt → MySQL** 전환 시에는 `DataStorage`만 수정했습니다.

### DB 테이블

| 테이블 | 컬럼 |
|---|---|
| `member` | id, name (UNIQUE) |
| `item` | id, name (UNIQUE) |
| `purchase` | id, item_name, buyer, cost, purchase_date, settled_date (NULL = 미정산) |

## 🚀 실행 방법

### 1. 저장소 받기

```bash
git clone https://github.com/slovelorn/roommate.git
```

Eclipse에서 **File → Import → Existing Projects into Workspace**로 프로젝트를 엽니다.
필요한 라이브러리(`lib/`)와 Build Path 설정(`.classpath`)이 포함되어 있어 별도 JAR 설정은 필요 없습니다.

### 2. DB 생성

MySQL Workbench 또는 cmd에서 `sql/schema.sql`을 **처음 한 번** 실행합니다.

```bash
mysql -u root -p < sql/schema.sql
```

> 이전 버전으로 DB를 이미 만든 경우에는 `sql/add_settled_date.sql`만 한 번 실행하면 됩니다.

### 3. DB 계정 설정

`src/db/DataStorage.java`의 `ID`, `PW`를 본인 MySQL 계정으로 바꿉니다.

```java
private static final String ID = "root";   // 자신의 MySQL 아이디로 변경
private static final String PW = "1234";   // 자신의 MySQL 비밀번호로 변경
```

> ⚠️ 실제 비밀번호로 바꾼 `DataStorage.java`는 **commit하지 마세요.**

### 4. LLM API 키 설정 (AI 자연어 입력 사용 시)

API 키는 코드에 넣지 않고 환경변수 `SUNMOON_API_KEY`로 읽습니다. 아래 중 한 가지 방법으로 등록합니다.

- **Windows 환경변수** (PowerShell / cmd, 등록 후 Eclipse 재시작)
  ```bash
  setx SUNMOON_API_KEY "발급받은_API_키"
  ```
- **Eclipse 실행 설정** : Run → Run Configurations → `Main` → Environment → `SUNMOON_API_KEY` 추가

> 키가 없어도 프로그램은 정상 실행되며, AI 자연어 입력만 "API 키가 설정되지 않았습니다"로 안내됩니다.

### 5. 실행

`src/app/Main.java` 우클릭 → **Run As → Java Application**
